# 光擎 SolarRestore Agent 初稿

## 项目名称

**光擎 SolarRestore Agent：全球光伏削峰还原自进化智能体平台**

推荐对外简称：**光擎 SolarRestore Agent**

## 一句话定位

把光伏削峰还原从“模型上线后的人工排查”升级为“生产自动运行、当天自动归因、问题样本回流、双模型灰度、自进化晋升”的 AI 业务闭环。

## 参赛亮点

- **真实业务痛点**：PCS 限功率、电网/卖电限制、负载侧约束会削平观测功率，导致真实 PV 能力、发电预测、收益分析和运营评估被低估。
- **生产级落地**：已接入 StarRocks、MySQL、Kafka、APScheduler、S3 等生产链路，按区域本地时区 19:45 自动运行。
- **Agent 重构流程**：编排、数据接入、检测/场景、还原、下发、分析、进化 Agent 串成端到端闭环。
- **线上真实数据验证**：demo 支持只读查询 StarRocks 9030 的 `sigen_device.pv_prediction_history`，可任意选择日期和站点。
- **容器日志实时归因**：demo 可接入公司 K8s Dashboard，读取 `data-platform` 下 `clipping/eff` 相关 Pod 日志，自动统计 ERROR/WARNING 和失败原因。
- **飞书交互闭环**：Agent 可发送飞书卡片，用户点击 Yes / No 后通过 WebSocket 回传，Agent 继续执行下一步。
- **模型持续进化**：原模型与 10000 站候选模型复用同一份输入并行推理，日终评估达标后晋升主模型。

## Demo 看板说明

- 首屏展示项目名称、生产入口、调度时间、Kafka 下发通道和参赛主张。
- “线上 StarRocks 9030 数据”支持输入任意 `dt`、`station_id`、`model_name`，统计 `predict_type=4` 的削峰还原入库站点数。
- “欧洲 K8s 实时日志”支持输入 namespace、关键词、tail 行数和 Pod 数，读取线上容器日志并自动归因。
- “飞书 Agent 提问模拟”可直接问运行状态、失败归因、区域风险、模型灰度、样本回流和线上 9030 统计。
- “飞书卡片交互闭环”可模拟确认卡片、点击 Yes / No、重复点击拦截和上下文压缩。
- 可视化包含欧洲线上样例 KPI、区域成功率、问题归因 Pareto、双模型灰度进度、Agent 闭环链路和参赛价值评分卡。

## 初稿诚实边界

- 区域定时调度、削峰检测与场景判定、Kafka 下发、WARNING 汇总和 ERROR 归因已上线。
- 线上 9030 查询已接入实际数据源；K8s 日志分析依赖有效 Dashboard token 和 RBAC 日志权限，demo 不持久化 token。
- 双模型并行处于灰度中，原模型和新 10000 站模型复用同一份输入。
- 高价值样本回流、数据集与场景标签重构已实现；自动训练、S3 发布和模型晋升仍属于规划/部分实现，后续需要继续固化训练流水线、评估指标和版本策略。

## 推荐展示话术

光擎 SolarRestore Agent 的价值不是单次训练一个削峰还原模型，而是把线上削峰还原业务做成可持续进化的 AI 系统。系统每天自动运行，发现削峰、判断场景、还原真实发电能力并下发结果；当天的失败原因会被分析 Agent 归因，再由进化 Agent 沉淀为高价值样本、重构数据集、训练新模型，并通过生产双模型灰度完成评估和晋升。

这套系统已经能接入线上 StarRocks 9030 查询真实结果，并能在具备有效 K8s Dashboard token 时读取 `data-platform` 容器日志做当天问题归因。同时，它通过飞书卡片把 Agent 决策纳入业务交互链路，形成“Agent 发起问题、用户确认、系统回调、Agent 继续执行”的可控闭环。
